# kube-ec2: self-managed HA Kubernetes on EC2

A production-shaped, self-managed Kubernetes cluster on AWS EC2, built from
first principles: kubeadm on immutable Packer AMIs, three control-plane nodes
across three AZs, private subnets only, public traffic through an NLB into
Gateway API (Envoy Gateway), Terraform in layered stacks applied by Atlantis,
and everything inside the cluster owned by Argo CD.

```
                       Internet
                          │
              ┌───────────▼───────────┐  public subnets (3 AZs)
              │ public NLB  80/443    │  TCP + Proxy Protocol v2, IP targets
              └───────────┬───────────┘
──────────────────────────┼───────────────────────────────────── private subnets
                          ▼
   ingress pool (tainted) Envoy pods ──▶ HTTPRoutes in namespaces labelled public
                                                 │
   internal NLB ──▶ same Envoy pods ──▶ routes for private namespaces
                                                 │
   system pool: Argo CD, controllers     general pool: workloads (cluster-autoscaler)
                                                 │
   internal API NLB :6443 ──▶ 3 × control plane (kubeadm, stacked etcd, 1 ASG per AZ)
                              hourly etcd snapshots → S3 (KMS)

   VPC endpoints (S3, ECR, STS, EC2, ELB, SSM, KMS, Logs, SQS, Auto Scaling) · NAT per AZ
```

## How the layers fit together

### One state per layer

Every layer has its own state key in one encrypted, versioned S3 bucket with
S3-native locking (`use_lockfile`, Terraform ≥ 1.10, no DynamoDB). The shared
part of the backend lives in `live/lab/backend.hcl`. Each layer sets only:

```hcl
backend "s3" { key = "30-cluster/terraform.tfstate" }
```

A broken plan in one layer can't touch another layer's resources, the blast
radius of an apply is one layer, and you can give different people or
pipelines access to different layers.

### Reading from each other: an SSM contract, not `terraform_remote_state`

Each layer publishes the values other layers need through
`modules/ssm-outputs`:

```
/kube-ec2/lab/10-network/private_subnet_ids   = ["subnet-…","subnet-…","subnet-…"]
/kube-ec2/lab/30-cluster/pool_ingress_security_group_id = sg-…
```

and consumers read single values with `data "aws_ssm_parameter"`. Compared
with `terraform_remote_state`:

- Consumers don't need read access to the producer's whole state file (which
  can contain secrets), only to specific parameters.
- The contract is explicit and small: renaming a resource inside a layer
  doesn't break consumers, as long as the parameter is still published.
- Non-Terraform consumers use the same values: the GitOps repo,
  `scripts/*.sh`, and humans (`aws ssm get-parameters-by-path`).

Never publish secrets this way; the module writes plain `String` parameters.

### Identities

| Identity | Can do |
|---|---|
| You (admin), locally | Apply `00-bootstrap`; assume the deployer role |
| Atlantis instance role | Read/write state; assume the deployer role. Nothing else. |
| Deployer role | Change infrastructure (AdministratorAccess for the lab, plus deny guardrails protecting the state bucket, its key, and the role itself) |
| GitHub Actions (`ami-build` environment) | Build AMIs via OIDC; no stored AWS keys |

Every provider in layers 05+ has `assume_role { role_arn = var.deployer_role_arn }`;
the backend uses the caller's own identity. "Can read state" and "can change
infrastructure" stay separate permissions.

### Execution order (Atlantis)

| Project | `execution_order_group` | `depends_on` |
|---|---|---|
| lab-10-network | 10 | |
| lab-20-identity | 20 | lab-10-network |
| lab-30-cluster | 30 | lab-10-network, lab-20-identity |
| lab-40-edge | 40 | lab-10-network, lab-30-cluster |
| lab-50-platform-iam | 50 | lab-20-identity, lab-30-cluster, lab-40-edge |

`atlantis apply` runs groups in order and aborts later groups on failure;
`depends_on` blocks applying a single layer before its dependencies in the
same PR. `when_modified` includes the modules each layer uses, plus
`../common.tfvars` and `../backend.hcl`, so a module change replans exactly
the layers that consume it.

## How a node becomes part of the cluster

Nothing runs kubeadm from outside. Every node boots the same AMI; user data
only writes `/etc/k8s-bootstrap/cluster.env` (role, pool, API endpoint, SSM
prefix…), and `k8s-bootstrap.service` does the rest:

- **Control plane:** the first node to atomically create
  `<runtime prefix>/init-lock` in SSM runs `kubeadm init` (secretbox
  encryption at rest, audit logging, IRSA issuer, no kube-proxy), publishes
  join material (token, CA hash, certificate key; KMS-encrypted), uploads
  the OIDC discovery docs, installs Cilium + AWS CCM + Argo CD + the root
  Application, and marks the cluster `initialized`. The others join as
  control-plane nodes.
- **Workers:** wait for `initialized`, read the token, join with their
  pool's labels and taints.
- **Day 2 (control plane timers):** refresh join material every 30 min,
  remove dead etcd members every 2 min (instance gone and endpoint
  unreachable), snapshot etcd to S3 hourly.

The runtime prefix contains a random "generation", so a destroyed and
re-created cluster never trips over the previous cluster's lock.

Atlantis never needs a kubeconfig, and nothing in Terraform talks to the
Kubernetes API.

## First run

Prerequisites: an AWS account, admin credentials locally, Terraform ≥ 1.10
(tested with 1.17), Packer ≥ 1.11, AWS CLI v2 + session-manager-plugin, a
public Route 53 zone, and this code in a GitHub repository.

1. **Configure.** Edit `live/lab/common.tfvars` (project, region,
   `github_repository`) and `live/lab/00-bootstrap/terraform.tfvars`
   (`admin_principal_arns`).

2. **Bootstrap state (local).**
   ```bash
   AWS_PROFILE=admin ./scripts/bootstrap-backend.sh lab
   ```
   Applies 00 with local state, writes `live/lab/backend.hcl`, migrates the
   state into S3, and fills `deployer_role_arn`. Commit both files.

3. **Atlantis (local).** Follow [docs/atlantis-github.md](docs/atlantis-github.md):
   create the GitHub App, put its secrets in SSM, apply `05-atlantis`, and
   protect `main`.

4. **First node AMI.** Either run the `node-ami` workflow (set the
   `ami-build` environment's variables `PACKER_ROLE_ARN` (from the 00
   outputs) and `AWS_REGION`, plus `BOT_APP_ID` / `BOT_APP_PRIVATE_KEY` for
   the PR bot), or build locally:
   ```bash
   cd packer && packer init . && packer build -var region=eu-central-1 .
   ```
   and put the AMI ID in `live/lab/30-cluster/ami.auto.tfvars`.

5. **Everything else through Atlantis.** Fill the placeholders in
   `30-cluster/terraform.tfvars`, `40-edge/terraform.tfvars` and
   `50-platform-iam/terraform.tfvars`, open a PR, review the plans, approve,
   comment `atlantis apply`, and merge. Layers 10 → 50 apply in order. For a
   first build, one PR per layer keeps cross-layer plans exact.

6. **Look at it.**
   ```bash
   ./scripts/get-kubeconfig.sh lab && ./scripts/get-kubeconfig.sh lab tunnel &
   KUBECONFIG=~/.kube/kube-ec2-lab.conf kubectl get nodes -o wide
   ```

## Cost (lab defaults, eu-central-1, rough)

3 NAT gateways (~$100/mo + data), 12 interface endpoints × 3 AZs (~$280/mo),
3 NLBs (~$50/mo + LCUs), 3 control-plane `t3.large` + 9 workers (3 pools × 3 AZs), plus
Atlantis. To cut it while learning, set `single_nat_gateway = true` and
shrink `interface_endpoints` in `10-network/terraform.tfvars`, and tear
down 30/40/50 when idle (see the runbook).

## Deliberate choices and known limits

- **Cilium in ENI IPAM mode** gives pods VPC IPs, so the NLB targets Envoy
  pods directly (no NodePort hop). Pods share their node's security groups,
  so east-west isolation is done with Cilium network/host policies, not SGs.
- **Terraform owns the NLBs**; aws-load-balancer-controller only registers
  pod IPs through `TargetGroupBinding`. The CCM's service controller is
  disabled, so `Service type=LoadBalancer` does nothing (block it with
  policy anyway).
- **Control-plane rolls are manual** (`scripts/roll-control-plane.sh`):
  an automatic instance refresh could replace etcd members faster than they
  rejoin.
- **Secrets at rest** use kubeadm's secretbox provider with the key in SSM
  (KMS-encrypted). A KMS v2 plugin is the stronger option to explore next.
- **IRSA issuer** is a public S3 bucket (two objects). If your account
  enforces S3 Block Public Access account-wide, front it with CloudFront.
- **Deployer role** is AdministratorAccess with guardrails. Split it into
  per-layer roles once the lab settles.
- Versions pinned at the time of writing: Terraform 1.17.1, AWS provider
  ~> 6.71, Kubernetes 1.36 (latest patch at build), Cilium 1.20.4, AWS CCM
  chart 0.0.12, Argo CD chart 10.11.6, Atlantis v0.49.0. Let Renovate bump
  them.
