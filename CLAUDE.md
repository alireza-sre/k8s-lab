Context for Claude Code sessions in this repository. Read this first; the

## What this is

A **learning lab that must still be production-grade and secure**: a
self-managed, highly available Kubernetes cluster on AWS EC2, built from first
principles. The owner has used EKS and a kubeadm homelab before; the goal is
to understand every layer. Later tracks (not built yet) will rebuild the
cluster layer with **Talos** and with **Ansible-driven kubeadm**, and the
design must stay portable to other VMs and bare metal.

Constraints that shape every change:

- **Public GitHub repository.** Never commit secrets, state, keys or
  `*.pem`. Assume strangers read everything and can comment on PRs.
- **Solo maintainer.** GitHub won't let you approve your own PR, so nothing
  may depend on PR approvals.
- **AWS Free plan account** (about $200 credits, ending around April 2027).
  The full lab burns roughly $30–40/day, so cost matters: prefer the cost
  levers, tear down layers 30/40/50 when idle. Joining AWS Organizations
  would irreversibly convert the account to a paid plan.
- The owner uses **WebStorm**, likes to see **diffs** and the **reasoning
  and trade-offs** behind a choice, and prefers automated/declarative
  mechanisms over hand-maintained lists.

## Architecture (one paragraph)

Three control-plane nodes (kubeadm, stacked etcd, one single-instance ASG
per AZ) behind an internal NLB on 6443; worker pools `system`, `ingress`,
`general` as one ASG per AZ each; everything in private subnets. Public
traffic: public NLB (TCP + Proxy Protocol v2, IP targets) → Envoy Gateway
pods on the tainted `ingress` pool → Gateway API routes, only for namespaces
labelled for public exposure; an internal NLB serves private namespaces.
Cilium in ENI IPAM mode (pods get VPC IPs, kube-proxy replaced). Terraform
owns the NLBs; aws-load-balancer-controller only registers pod IPs via
`TargetGroupBinding`. The AWS cloud controller manager runs with its service
and route controllers disabled. Everything inside the cluster belongs to
Argo CD (GitOps); Terraform stops at the AWS boundary.

## Conventions (keep these)

**One state per layer.** Each layer sets only `backend "s3" { key = "<layer>/terraform.tfstate" }`;
bucket/region/KMS/`use_lockfile` come from `../backend.hcl`. S3-native
locking, no DynamoDB.

**Cross-layer data goes through the SSM contract, never `terraform_remote_state`.**
Producers publish with `modules/ssm-outputs` under
`/<project>/<env>/<layer>/<key>` (lists/maps JSON-encoded, never secrets);
consumers read with `data "aws_ssm_parameter"`. The GitOps repo and
scripts read the same parameters.

**Credentials.** Nothing in code names an AWS profile. The backend uses the
caller's ambient identity (your profile locally, the instance role on
Atlantis) to read/write state; every provider from layer 05 on has
`assume_role { role_arn = var.deployer_role_arn }` to change resources.
00-bootstrap's provider has no `assume_role` (it creates the deployer).
The root user can never assume roles; use the admin IAM user (or later IAM
Identity Center).

**Variables.** Every layer has an identical `common.tf` declaring the common
variables plus `local.name` (`<project>-<env>`), `local.prefix`
(`/<project>/<env>`) and `local.layer`. Plans run with
`-backend-config=../backend.hcl` and `-var-file=../common.tfvars`
(`terraform.tfvars` in the layer auto-loads).

**Names.** IAM and S3 names are global; bucket names end in the account ID.
LB/target-group names have a 32-char limit, which is why `cluster_name` is
validated at 20 chars or fewer.

**Nodes are immutable.** No `unattended-upgrades`; the weekly `node-ami`
workflow rebuilds the AMI and opens a PR bumping
`live/lab/30-cluster/ami.auto.tfvars`. Worker pools roll via ASG instance
refresh; the control plane only via `scripts/roll-control-plane.sh` (one
node at a time; never add instance_refresh to control-plane ASGs).

**Node bootstrap** (`packer/files/k8s-bootstrap/`): user data only writes
`/etc/k8s-bootstrap/cluster.env`. The first control-plane node to create the
SSM parameter `<runtime prefix>/init-lock` runs `kubeadm init` (secretbox
encryption at rest, audit policy, IRSA issuer, no kube-proxy), publishes
KMS-encrypted join material, uploads the OIDC discovery docs, installs
Cilium + AWS CCM + Argo CD + the root Application, and writes
`initialized`. Others join. Timers: join material refresh (30 min), stale
etcd member removal (2 min), etcd snapshot to S3 (hourly). The runtime
prefix includes a random "generation" so a recreated cluster never sees an
old lock.

## Atlantis

- Server-side `repos.yaml` (rendered from `modules/atlantis/templates/`)
  allows only the `layered` workflow; `allow_custom_workflows: false`.
- **Authorization** (personal account, so no team allowlist): the first step
  of every plan/apply runs `authz-check`. Plans need an authorized PR author
  (`authorized_users` or `authorized_pr_bots`); plans with extra args after
  `--` and all applies need the commenter in `authorized_users`. Lists are
  Terraform vars in `05-atlantis/terraform.tfvars`, stored in SSM, synced
  into the container every minute (no instance replacement).
  `ATLANTIS_ALLOW_COMMANDS=version,plan,apply,unlock`. Fork PRs are ignored.
- `apply_requirements` default `[mergeable, undiverged]` (no `approved`,
  see "solo maintainer").
- Changing anything in Atlantis's **user data** replaces the instance
  (`user_data_replace_on_change = true`) and drops its locks and plans.
- Layers 00 and 05 are not in `atlantis.yaml`; apply them locally.

## GitHub Actions

- `node-ami.yml`: the `build` job assumes `k8s-lab-lab-github-packer` via
  OIDC. The repo uses GitHub's **immutable OIDC subjects**, so the role
  trusts `<github_oidc_subject_prefix>:environment:ami-build`, i.e.
  `repo:<owner>@<id>/<repo>@<id>:…` (case-sensitive; set in
  `00-bootstrap/terraform.tfvars`, validated against `github_repository`). The `propose` job opens the PR as a separate GitHub App
  (repo-level `BOT_APP_ID` variable, `BOT_APP_PRIVATE_KEY` secret) so
  `checks.yml` runs on it. Setup: `docs/github-actions.md`.
- `checks.yml`: fmt, validate (every module and layer), tflint, shellcheck,
  packer validate, yamllint, Trivy (SARIF upload needs `actions: read`).
- Never use `pull_request_target`. Pin third-party actions to commit SHAs
  (`hashicorp/setup-packer@main` in node-ami.yml is still unpinned).

## Design decisions already made (don't relitigate without a reason)

- Two Argo CD instances: platform (cluster-admin, manages add-ons and
  tenant namespaces) and tenant (namespace-scoped). Hub-and-spoke later.
- Immutable AMIs over runtime Ansible on AWS; Ansible stays for bare metal.
- Add-ons are not Terraform-managed (Terraform creates only their IAM/KMS/
  SQS/DNS dependencies in 50-platform-iam).
- Multi-account/region, if ever: separate layer folders per account
  (symlinked shared `.tf`), per-account deployer roles trusting the
  Atlantis role, `allowed_account_ids` in providers, region code in names.
